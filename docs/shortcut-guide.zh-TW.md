# iOS 設定捷徑

一個捷徑，開啟 iOS 設定裡的任何一個頁面。你用中文或英文關鍵字搜尋，再從清單選一個。

## 檔案

檔案在 `shortcuts/zh-TW/`。

| 檔案 | 內容 | 建議 |
| --- | --- | --- |
| `iOS 設定捷徑.shortcut` | 1758 筆。iPhone 與 iPad 可用、而且有名稱的頁面。 | 日常用這個。 |
| `iOS 設定捷徑 完整版.shortcut` | 1878 筆。加上沒有名稱、或只在舊版 iOS 有效的項目。 | 找冷門項目才用。 |
| `Apple Watch 設定捷徑.shortcut` | 711 筆。`bridge:` 開表的設定頁。 | 有 Apple Watch 才裝。 |
| `unsigned/*.shortcut` | 同樣內容，沒有簽章。 | 簽章檔匯入失敗時的備案。 |

英文介面的版本在 `shortcuts/en/`。

三個檔加起來是全部 2589 筆。本來是一個大檔，Apple 的簽章服務比較容易拒絕大檔，所以拆開。
`bridge:` 只能在 iPhone 上的「Watch」App 裡開，與 iPhone 設定沒有關係。

## 怎麼裝

### 方法一：AirDrop（最簡單）

1. 在 Mac 上選 `.shortcut` 檔。
2. 用 AirDrop 傳到 iPhone。
3. iPhone 會打開「捷徑」App。點「加入捷徑」。

### 方法二：先在 Mac 匯入，讓 iCloud 同步

1. 在 Mac 上按兩下 `.shortcut` 檔。
2. Mac 的「捷徑」App 會問你要不要加入。點「加入捷徑」。
3. iPhone 開同一個 Apple 帳號，捷徑會自己同步過去。

注意：在 Mac 上執行沒有用。`prefs:` 是 iOS 專用的。Mac 的系統設定用別的協定。

### 方法三：用未簽章的檔案

只有在上面兩個方法失敗時才需要。

1. 先在 iPhone 上執行過任何一個捷徑一次。
2. 到「設定」→「捷徑」，打開「允許不受信任的捷徑」。
3. 把 `unsigned/` 裡的檔案傳到 iPhone，再打開它。

## 怎麼用

1. 執行捷徑。
2. 輸入關鍵字。中文或英文都可以。例如 `藍牙`、`wifi`、`螢幕使用時間`、`keyboard`。
3. 直接按「完成」不打字，就會列出全部項目。
4. 從清單點一個，設定 App 就會跳到那一頁。

搜尋是文字比對。它同時比對中文名稱、英文名稱和 URL 本身。
所以你也可以用 `BATTERY` 或 `root=CAMERA` 這種寫法找。

清單排序是主頁面在前，子項目在後。所以搜「藍牙」時，第一筆就是「藍牙」主頁。

## 捷徑裡面做了什麼

九個動作：

1. **文字** — 存放整份清單。每一行是 `中文 ｜ English ⇢ url`。
2. **要求輸入** — 問你關鍵字。
3. **替換文字** — 把關鍵字裡的特殊符號換成 `.`，避免正則表示式出錯。
4. **比對文字** — 用 `(?im)^.*關鍵字.*$` 取出符合的行。
5. **從列表中選取** — 顯示符合的行。
6. **分開文字** — 用 ` ⇢ ` 切開。
7. **從列表取得項目** — 取最後一項，就是 URL。
8. **URL** — 轉成網址型別。
9. **打開 URL** — 開啟設定頁。

### 為什麼要自己做搜尋

「從選單中選擇」沒有搜尋。「從列表中選取」在 iOS 13 有搜尋列，iOS 14 之後被 Apple 拿掉。
所以搜尋要靠第 2 到第 4 個動作自己做。

## 已知限制

1. 清單很長。在「捷徑」App 裡編輯第一個文字動作會很慢。執行則不受影響。
2. 關鍵字沒有比對到任何一行時，「從列表中選取」會因為清單是空的而報錯。重跑一次換個字即可。
3. 有些 URL 只在舊版 iOS 有效。完整清單的「系統檔驗證」欄位寫明哪一版有。
4. `prefs:` 不是公開 API。放進自己的 App 送審可能被退件。在「捷徑」App 裡用沒有這個問題。

## 重新產生

```sh
make fetch      # 下載來源到 raw/
make merge      # 合併 -> data/settings-urls.json
make docs       # 產生 docs/settings-urls.md
make shortcuts  # 產生未簽章的 .shortcut
make sign       # 簽章
make verify     # 檢查動作接線與搜尋邏輯
```
